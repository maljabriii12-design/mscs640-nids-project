\begin{abstract}
Signature-based defences miss novel attacks, and on flow data the attacks a
SOC cares about are rare. We build an end-to-end pipeline for 15-class
intrusion detection on CSE-CIC-IDS2018~\cite{sharafaldin2018}. It streams
\NumRawFlows{} raw flows in chunks, removes non-finite values, repeated headers
and duplicates, resolves flows whose identical features carry conflicting labels
by a sampling-corrected majority vote, and builds a class-capped sample of
\NumSampleFlows{} flows. Feature selection reduces \NumFeaturesIn{} flow
statistics to \NumFeaturesOut{}. Class imbalance is handled on the training
split only, by Benign under-sampling, SMOTE~\cite{chawla2002} and damped class
weights. We compare a Random Forest baseline, gradient-boosted trees, an MLP
and their soft-voting ensemble, then tune per-class decision weights on
validation macro-$F_1$. The selected model, \BestModel{}, reaches a test
macro-$F_1$ of \BestMacroFOne{} and detects \DetectionRate{} of attack flows at a
false-positive rate of \FalsePositiveRate{}. A benign-only autoencoder adds
label-free anomaly scores for previously unseen attacks. The trained model is
served through a web dashboard that turns an uploaded CSV into a triaged
threat report.
\end{abstract}

\section{Introduction}
Machine-learning network intrusion detection systems (NIDS) learn attack
behaviour from flow statistics instead of payload signatures, and
CSE-CIC-IDS2018~\cite{sharafaldin2018} has become a common benchmark for
them~\cite{leevy2020}. Two properties make it harder than headline accuracies
suggest. First, it is severely imbalanced: Benign flows outnumber the rarest
attack, SQL Injection, by about five orders of magnitude, so accuracy rewards a
model that ignores attacks. Second, the released CSVs contain labelling and
processing errors, documented for the related CIC-IDS2017~\cite{engelen2021}
and for both datasets~\cite{liu2022}.

Earlier work on this dataset oversampled the minority classes with SMOTE before
training classical learners such as Random Forest and gradient
boosting~\cite{karatas2020}, or trained an attention-based LSTM with SMOTE and a
class-weighted loss, reporting 96.2\% overall accuracy~\cite{lin2019}. On this
class distribution an overall accuracy says little about the rare attacks. We
therefore optimise and report \emph{macro}-$F_1$, in which every class counts
equally, and treat data engineering as part of the method.

Our contributions are: (i) a memory-bounded, two-pass data pipeline for the
full 6.4\,GB dataset; (ii) a controlled comparison of tree ensembles and an
MLP under the same rebalancing; (iii) validation-tuned class-bias weights,
which raise macro-$F_1$ without touching the test set; and (iv) a deployed
dashboard that pairs the supervised classifier with an unsupervised anomaly
score.

\section{Dataset and Data Engineering}
\subsection{Data}
The ten ``Processed Traffic Data for ML Algorithms'' files contain one
CICFlowMeter record per bidirectional flow: 79 columns plus the
\texttt{Label}, and one day (20-02-2018) adds \texttt{Flow ID},
\texttt{Src IP}, \texttt{Src Port} and \texttt{Dst IP}. Each day has Benign
traffic plus only the attacks staged that day, so the training set is drawn
across all days. Table~\ref{tab:data} lists the classes, using the dataset's
own spellings.

\subsection{Cleaning}
Reading proceeds in chunks of 250k rows, so no file is ever fully loaded.
Every chunk is cleaned as follows. (a) Header lines repeated mid-file are
removed. (b) Identifier and time columns (\texttt{Timestamp}, IPs, source
port, flow ID) are dropped: they describe the testbed rather than the
behaviour of the flow, and a model that used them would learn which host
attacked on which day. (c) All features are coerced to numbers.
\texttt{Infinity} and \texttt{NaN}, which appear in \texttt{Flow Byts/s} and
\texttt{Flow Pkts/s} when a flow has zero duration, become missing values and
are later imputed with the training median. Values outside the
\texttt{float32} range are clipped. (d) After sampling, exact duplicates are
removed. Feature vectors that occur with more than one label cannot be
separated by any model that sees only these features, so each is reduced to a
single copy labelled with the class it carries most often in the \emph{full}
data. Because classes are sampled at different rates (Sec.~\ref{sec:sampling}),
the sample counts are first divided by each class's sampling probability;
otherwise the down-sampled Benign class would be under-counted. This choice is
the Bayes-optimal label for an indistinguishable vector, and it matters here:
in our nine-day pilot run, the obvious alternative of dropping every
conflicting copy cut \emph{FTP-BruteForce} from 193{,}360 flows to 2 and
\emph{DoS-SlowHTTPTest} from 139{,}890 to 3, because almost all flows of these
two classes share the same feature vectors. Both classes then vanished from the
test split, and a 12-class test macro-$F_1$ of 0.934 hid a model that could
never recognise them. With majority resolution both classes survive
(24 and 33 distinct flows), and every one of the 15 labels reaches the test set.
This is consistent with the labelling problems documented for this
dataset~\cite{liu2022}.

\subsection{Sampling}\label{sec:sampling}
A first pass reads only the \texttt{Label} column and counts every class. A
second pass keeps each row with probability $\min(1, c/n_y)$, where $n_y$ is
the class count and $c$ is a cap (1M for Benign, 200k for each attack). Rare
classes are therefore kept in full, and the sample fits in laptop memory. The
de-duplicated sample is split 70/15/15 into stratified train, validation and
test sets. The validation set is used for early stopping, model selection and
decision tuning; the test set is used exactly once.

\subsection{Feature selection}
All selection is fitted on the training split. Each feature is median-imputed,
clipped to its $[10^{-4}, 1-10^{-4}]$ training quantiles, transformed with
$\operatorname{sign}(x)\log(1+|x|)$, which tames the heavy-tailed byte, rate
and duration features, and standardised. We then (1) drop zero-variance
columns (several bulk-rate and URG/PSH columns are constant), (2) rank
features with a class-balanced Extremely Randomized Trees
model~\cite{geurts2006} and, within every group whose pairwise $|r|>0.98$,
keep only the highest-ranked feature, and (3) keep the top 40. Fig.~\ref{fig:imp}
shows the resulting importances. The two top-ranked features,
\texttt{Init Fwd Win Byts} and \texttt{Fwd Seg Size Min}, describe the initial
TCP window and the smallest forward segment; they act as a fingerprint of the
attacking tool's TCP stack, which a scripted flood or brute-force client keeps
constant across thousands of flows. They are followed by rate and timing
features (\texttt{Flow Pkts/s}, \texttt{Flow Duration}, \texttt{Flow IAT Mean},
\texttt{Fwd IAT Max}, \texttt{Bwd Pkts/s}), which separate high-rate floods
(Hulk, HOIC, LOIC) from low-and-slow attacks (Slowloris, SlowHTTPTest), and by
\texttt{Dst Port}, which names the targeted service (21 for FTP, 22 for SSH, 80
for the web attacks). The window and port features may partly reflect the
testbed configuration rather than attack behaviour, a caveat for deployment on
other networks that the day-held-out evaluation in Sec.~\ref{sec:conc} would
test.

\subsection{Class imbalance}
Imbalance handling is applied to the training split only, so the validation
and test sets keep the natural class mix. Benign is under-sampled to 600k
flows. Every class below 20k flows is lifted to 20k with
SMOTE~\cite{chawla2002}, which interpolates between a flow and one of its
$k{=}5$ nearest same-class neighbours in the standardised log space. All
models are trained with class weights $w_c=(n_{\max}/n_c)^{0.5}$, normalised
to a mean of 1. The exponent $0.5$ is a deliberate damping: once SMOTE has
lifted the rare classes, full inverse-frequency weighting costs Benign
precision, and with it the false-positive rate that an analyst actually
experiences.

\section{Models and Methodology}
\textbf{Random Forest} (baseline)~\cite{breiman2001}: 100 trees,
$\sqrt{d}$ features per split, 25\% bootstrap samples, depth $\le 25$, at
least 3 samples per leaf (a deliberate cap on model size and memory).
\textbf{Gradient-boosted trees}: XGBoost~\cite{chen2016} with histogram
splits (scikit-learn's LightGBM-style histogram GBDT~\cite{ke2017} as a
fallback); learning rate 0.1, depth 8, L2 penalty 1, up to 600 rounds with
early stopping on validation log loss. \textbf{MLP}: three ReLU layers (256-128-64), Adam~\cite{kingma2015},
batch size 1024, L2 penalty $10^{-4}$, early stopping, and the class weights
above applied to the cross-entropy loss. \textbf{Ensemble}: the average of the
three models' class probabilities. All models use
scikit-learn~\cite{pedregosa2011}.

\textbf{Class-bias decision rule.} The arg-max of the posterior is optimal
for accuracy, not for macro-$F_1$. For each model we learn non-negative weights
$\mathbf{w}$ and predict $\arg\max_c w_c\,p(c\mid x)$. The weights are found
by coordinate ascent over a log-spaced grid that maximises
\emph{validation} macro-$F_1$. Model selection likewise compares validation
macro-$F_1$ only.

\textbf{Hyper-parameter tuning.} \texttt{python main.py train --tune} runs a
random search (12 trials) over the GBDT learning rate
$\{0.03,0.05,0.1,0.2\}$, depth $\{6,8,10,12\}$ and L2 penalty
$\{0,0.5,1,5\}$ on a 150k-flow subsample of the rebalanced training set,
scored by validation macro-$F_1$ (20 minutes in total). Validation macro-$F_1$
ranged from 0.867 to 0.889. The best trial (learning rate 0.1, depth 8,
L2~1.0) coincided with the defaults above, so retraining on the full data
reproduced the untuned scores exactly: within this range the model is not
sensitive to these settings, and the largest effects come from the data
engineering and the class-bias step instead. (The search space also listed a
leaf cap, which the XGBoost engine did not receive at the time; this has since
been fixed, and the 12 trials were distinct in the other three settings.)

\textbf{Autoencoder.} A 32-8-32 bottleneck network is trained to reconstruct
Benign training flows only. A flow is flagged when its reconstruction error
exceeds the 99th percentile of errors on Benign validation flows. The
autoencoder never sees an attack label, so it complements the classifier on
attack types missing from training.

\textbf{Models.} Gradient-boosted trees beat the Random Forest baseline
(test macro-$F_1$ 0.849 vs 0.806), and the MLP is weakest (0.765) despite the
longest training time, which matches the usual advantage of tree ensembles on
tabular flow statistics. The class-bias step is the single largest gain: it
adds 0.015 to XGBoost, 0.075 to the Random Forest and 0.076 to the MLP,
because it moves decisions in favour of the rare classes without retraining.
Selection on validation picks XGBoost with class bias (0.942 validation,
0.864 test); the Random Forest with class bias scores slightly higher on test
(0.880), but choosing it after looking at the test set would bias the
estimate, so we report the validation choice.

\textbf{Where the model fails.} Fig.~\ref{fig:cm} shows three failure modes.
(i) Half of the \emph{Infilteration} flows (51\%) are classified Benign, and
4\% of Benign flows are flagged as Infilteration: at the flow level an
infiltrated host's traffic looks like ordinary browsing, which also explains
most of the 4.5\% false-positive rate. (ii) \emph{DoS-SlowHTTPTest} and
\emph{FTP-BruteForce} are confused with each other (60\% and 25\% of their
test flows), as expected from the shared feature vectors found in
Sec.~\ref{sec:sampling}. (iii) \emph{SQL Injection} spreads to Brute Force
-Web (17\%), Brute Force -XSS (8\%) and Infilteration (17\%), since all three
web attacks hit the same application with similar request shapes;
Brute Force -Web and -XSS themselves are rarely confused with each other.
All other attacks are detected almost perfectly.

\textbf{Reliability of the numbers.} The test split holds only 4
FTP-BruteForce, 5 SlowHTTPTest and 12 SQL Injection flows, so a single flow
moves their $F_1$ by 0.1--0.25. This, rather than overfitting, is the main
reason for the gap between validation and test macro-$F_1$. The
autoencoder reaches an AUC of \AEAUC{} but detects only \AEDetectionRate{}
of attacks at \AEFalsePositiveRate{} false positives, so it is useful as a
secondary signal for unknown traffic, not as a standalone detector.

\section{Deployment}
A Flask dashboard (\url{https://ids.batch5ai.lol}) scores an uploaded
CICFlowMeter CSV with the frozen bundle and returns a threat report: attack
mix and severities, most-targeted hosts and ports, a triage table, flows that
are anomalous yet classified Benign, and live metrics when labels are present.
It runs on a 1~GB cloud VM and scores 5{,}000 flows in about 2~s.

\section{Conclusion and Future Work}\label{sec:conc}
On a heavily imbalanced, artefact-laden benchmark, careful data engineering
(de-duplication, sampling-corrected resolution of label conflicts, train-only
rebalancing) and
macro-$F_1$-driven decisions matter as much as the choice of classifier.
Future work: (i) evaluate on a day-held-out split, to measure generalisation
to new attack campaigns rather than to new flows from the same campaign;
(ii) use the corrected re-labelling of the dataset~\cite{liu2022};
(iii) add sequence models (CNN-1D or recurrent) over windows of flows per
host, since slow attacks such as Slowloris and infiltration are visible across
flows rather than within one; and (iv) calibrate the autoencoder threshold
for a target alert budget.
